# Composed Proportional Assurance Pressure Tests

Owner: `coding-project-orchestrator`

This evaluator checks whether one orchestrator consequence/gate decision survives diagnosis, artifact, planning, coder, verification, review, closure, preservation, profile, and harness-adapter boundaries. Owner-local pressure suites remain authoritative for their narrower owner behavior.

Test posture: `TEST_AFTER_WITH_REASON`. Runtime/control sources had to become coherent before these cross-owner scenarios could exercise the final contract. Fresh target behavior is the acceptance seam; source inspection alone is not behavioral proof.

## Isolation And Identity Contract

- Dispatch every packet in a fresh named non-inheriting session with `fork_turns: "none"`.
- Give the target the repository working directory, normal system/harness instructions, repository-root `AGENTS.md`, the exact packet prompt, and only the packet's closed runtime-file list.
- Targets are read-only. They must not edit files, write scratch state, invoke subagents, dispatch workflows, mutate external systems, or run source-control mutations.
- A target must not read any repository path outside its closed list. It reports exact paths read and confirms no mutation.
- Evaluator criteria, expected outcomes, prior results, and the approved source artifacts are evaluator-only.
- Preserve the exact raw target output. The target does not score itself.
- Any source/evaluator/prompt/criterion mutation after dispatch invalidates the affected result. Stage B may populate the predeclared report result sections while preserving frozen prompt and criterion bytes; it must record the report's final identity separately.

Prompt identity is SHA-256 over the exact UTF-8 bytes inside each `TARGET-PACKET` fenced block, excluding the opening/closing fence lines and the single terminating newline. Criterion identity is SHA-256 over the exact UTF-8 bytes of the corresponding complete row in the acceptance matrix, excluding its terminating newline.
